# vzMusic

Минималистичное музыкальное PWA (Next.js App Router + TypeScript + Tailwind v4), которое стримит аудио из YouTube Music через `youtubei.js` и продолжает играть в фоне на iPhone при заблокированном экране.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
```

### Деплой на Vercel

1. Импортируйте репозиторий на vercel.com → **New Project** (фреймворк определится сам).
2. Переменные окружения (все необязательные, пример — `.env.example`):
   | Переменная | Назначение |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Включают вход через Google и облачную синхронизацию (см. ниже). Без них данные живут только в браузере. |
   | `YT_COOKIE` | Cookie вашего аккаунта YouTube — только если YouTube блокирует сервер Vercel ошибкой «Sign in to confirm you're not a bot». |
   | `YT_CLIENTS` | Порядок InnerTube-клиентов для получения потока, по умолчанию `ANDROID_VR,IOS,TV,WEB_EMBEDDED,MWEB`. |
   | `YT_LOCATION` | Регион каталога (`US` по умолчанию). |
   | `NEXT_PUBLIC_STREAM_API_URL` | Адрес отдельного сервера для `/api/*`. Пусто — API работает в этом же проекте на Vercel. |
3. На iPhone: Safari → «Поделиться» → **На экран «Домой»**.

### Supabase + вход через Google

1. Создайте проект на [supabase.com](https://supabase.com).
2. **SQL Editor** → вставьте содержимое `supabase/schema.sql` → **Run**. Создадутся таблицы `tracks`, `likes`, `playlists`, `playlist_items`, `user_artists`, `plays`, `user_state` с RLS: каждый видит только свои строки. Файл можно запускать повторно.
3. **Google Cloud Console** → APIs & Services → Credentials → **Create OAuth client ID** (Web application).
   - Authorized redirect URI: `https://<ваш-проект>.supabase.co/auth/v1/callback`
4. Supabase → **Authentication → Sign In / Providers → Google** → включите, вставьте Client ID и Client Secret.
5. Supabase → **Authentication → URL Configuration**:
   - Site URL: `https://<ваш-домен>.vercel.app`
   - Redirect URLs: `https://<ваш-домен>.vercel.app/**` (и `http://localhost:3000/**` для разработки)
6. Supabase → **Project Settings → API**: скопируйте Project URL и anon (publishable) key в `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` на Vercel и сделайте Redeploy.

Кнопка «Войти» появится в «Медиатеке». При первом входе локальные лайки/плейлисты объединяются с облачными; дальше изменения отправляются в Supabase через 1,5 с, а при возвращении в приложение подтягиваются изменения с других устройств.

### Как получить `YT_COOKIE` (только если нужно)

1. В браузере на компьютере войдите в music.youtube.com (лучше отдельным, не основным аккаунтом).
2. DevTools (F12) → вкладка **Network** → обновите страницу → кликните любой запрос к `music.youtube.com` → **Request Headers** → скопируйте значение заголовка `cookie` целиком.
3. Вставьте эту строку в `YT_COOKIE` на Vercel и сделайте Redeploy. Никому её не показывайте — это доступ к аккаунту.

**Чтобы cookie жила долго:**
- копируйте её в окне инкогнито и сразу закрывайте окно, **не нажимая «Выйти»** (выход мгновенно отзывает cookie);
- не открывайте этот аккаунт в обычном браузере — Google «поворачивает» cookie при активности, и старая копия перестаёт работать;
- после смены региона функций на Vercel cookie может быть отозвана — скопируйте заново;
- проверить её можно в «Настройки → Проверить YouTube» (`/api/debug`): `account_ok: true` — cookie жива; `cookie_missing` — какие важные cookie не скопированы.

Если YouTube отвечает «Sign in to confirm you're not a bot» на все клиенты, сервер на 3 минуты перестаёт обращаться к YouTube, чтобы не усугублять блокировку.

## Домашний сервер на Banana Pi (бесплатно, без cookie)

Маленький компьютер дома (BPI-M4 Zero, Raspberry Pi, старый ноутбук с Linux) работает сервером для сайта:
YouTube видит ваш домашний IP — cookie и прокси не нужны. Сайт на Vercel остаётся интерфейсом и работает
где угодно (мобильный интернет, другая страна); музыку он берёт с BPI по публичному HTTPS-адресу
Tailscale Funnel. Если BPI недоступен, сайт автоматически переключается на собственный API Vercel.

**Установка** (Armbian / Debian / Ubuntu, arm64; по SSH или с клавиатурой):
```bash
git clone https://github.com/vadymzelenko/freemusic.git && cd freemusic
sudo bash scripts/bpi/setup.sh
```
Скрипт ставит Node.js 22, включает swap, собирает проект (5–15 минут), запускает сервис `vzmusic`
(автозапуск после перезагрузки/отключения света), включает ночное автообновление из GitHub и публикует
сервер через Tailscale Funnel. В конце он покажет адрес вида `https://bpi.tailXXXX.ts.net`.

Дальше: Vercel → Settings → Environment Variables → `NEXT_PUBLIC_STREAM_API_URL` = этот адрес → Redeploy.

Полезные команды на BPI:
```bash
systemctl status vzmusic          # работает ли сервер
journalctl -u vzmusic -f          # логи
sudo bash scripts/bpi/update.sh   # обновить вручную
tailscale funnel status           # публичный адрес
```
Если репозиторий приватный, клонируйте с токеном GitHub (`git clone https://<token>@github.com/...`) — иначе
автообновление не сможет скачивать изменения.

## Полностью автономно: резидентный прокси (рекомендуется)

Сайт (PWA) работает одинаково на Android, iPhone, Mac и Windows, но его сервер (Vercel) YouTube блокирует
по IP дата-центра. Решение без cookie и без включённого компьютера — пустить запросы сервера к YouTube
через **прокси с домашним (residential / ISP) IP**:

1. Купите **статический резидентный (ISP) прокси**, протокол **HTTP**, страна рядом с вами
   (например Польша/Германия). Подойдёт любой провайдер, где есть «Static Residential / ISP proxy»:
   Webshare, IPRoyal, Proxy-Cheap, Decodo и т.п. Обычно это 2–6 $/мес за 1 IP.
   Предпочтительнее тариф без лимита трафика: через прокси идёт и аудио (~4–5 МБ на трек).
2. Vercel → Settings → Environment Variables → `YT_PROXY_URL` = `http://логин:пароль@хост:порт` → Redeploy.
3. Vercel → Settings → Functions → Function Region — выберите ближайший к прокси (например `fra1`).
4. Откройте Настройки → «Проверить YouTube»: `proxy: true`, `outbound_ip` — IP прокси, клиенты зелёные.
   `YT_COOKIE` после этого можно удалить.

## Приложение для iPhone и Android (без cookie)

Нативное приложение — это оболочка Capacitor (`ios/`, `android/`). Интерфейс загружается с вашего сайта
(обновления приходят сразу, переустанавливать не нужно), а **YouTube-движок работает на самом телефоне**
(`lib/native/engine.ts`): поиск, радио и получение аудио идут нативными запросами с IP телефона —
поэтому cookie и сервер для музыки не нужны. Аудио играет напрямую из Google, скачанное хранится в файлах
приложения. Без интернета открывается встроенный офлайн-экран со скачанными треками.

> Сначала задеплойте эту версию на Vercel: приложение загружает интерфейс оттуда.
> Если домен не `vzmusic.vercel.app`, поменяйте `server.url` в `capacitor.config.ts`.

### iPhone (Mac + Xcode, бесплатный Apple ID)
1. Установите **Xcode** из App Store, откройте его один раз и согласитесь с лицензией.
2. В терминале:
   ```bash
   git clone https://github.com/vadymzelenko/freemusic.git && cd freemusic
   npm install
   npm run ios          # = npx cap sync ios && npx cap open ios
   ```
3. В Xcode: слева выберите **App** → вкладка **Signing & Capabilities** →
   **Team** → *Add an Account…* → войдите своим Apple ID → выберите «(Personal Team)».
   Если ругается на Bundle Identifier — поменяйте `com.vzmusic.app` на что-то уникальное, например `com.<вашеимя>.vzmusic`.
4. Подключите iPhone кабелем, разблокируйте, нажмите «Доверять». Выберите iPhone вверху Xcode и нажмите **▶ Run**.
5. На iPhone: **Настройки → Основные → VPN и управление устройством** → ваш Apple ID → *Доверять*.
   Для iOS 16+ также включите **Настройки → Конфиденциальность → Режим разработчика** (iPhone перезагрузится).
6. С бесплатным Apple ID приложение работает **7 дней**. Потом просто подключите iPhone и снова нажмите ▶ Run —
   данные (лайки, скачанное) сохранятся.

### Android
- **Без Android Studio:** GitHub → вкладка **Actions** → **Android APK** → *Run workflow* (или любой пуш в `main`
  с изменениями в `android/`) → в готовом запуске скачайте артефакт **vzmusic-apk**, распакуйте и откройте
  `app-debug.apk` на телефоне (разрешите установку из этого источника).
- **С Android Studio:** `npm run android` → ▶ Run.

**Вход через Google в приложении:** добавьте в Supabase → Authentication → URL Configuration → Redirect URLs
адрес `com.vzmusic.app://auth-callback`. Вход открывается в системном браузере и сам возвращает в приложение.

На Android во время воспроизведения висит уведомление «vzMusic» — это сервис, который не даёт системе
остановить музыку при выключенном экране.

## Сайт без cookie: Mac как мост

Сайту в браузере нужен сервер (браузеру CORS не даёт обращаться к YouTube), а IP Vercel YouTube блокирует.
Выход — запускать API на вашем Mac (домашний IP YouTube не блокирует) и открыть его в интернет через
бесплатный **Tailscale Funnel** с постоянным адресом:

1. На Mac в папке проекта: `npm install`, затем `npm run bridge` (API на порту 3939; держите окно открытым
   или запустите через `pm2`).
2. Установите Tailscale (tailscale.com/download), войдите и выполните: `tailscale funnel --bg 3939`.
   Команда покажет адрес вида `https://mac-name.tailXXXX.ts.net`.
3. Vercel → Settings → Environment Variables → `NEXT_PUBLIC_STREAM_API_URL` = этот адрес → **Redeploy**.

Теперь сайт берёт музыку через Mac, а `YT_COOKIE` можно удалить. Пока Mac выключен, музыка на сайте
работать не будет (приложению на телефоне мост не нужен).

## Возможности

- **Главная**: «Мой микс», «Открытия», миксы по вашим артистам, «Быстрый выбор», «Потому что вам понравилось…», недавнее и любимое.
- **Онбординг**: выбор любимых артистов по жанрам, сразу подсказываются похожие. Изменить можно в «Настройках».
- **Поиск**: подсказки при вводе, вкладки «Всё / Треки / Альбомы / Артисты», мгновенный поиск по своей медиатеке.
- **Страницы артиста и альбома**, «В мои артисты», радио артиста.
- **Лайки и дизлайки**: дизлайк навсегда убирает трек из рекомендаций и понижает артиста.
- **Скачивание** треков, альбомов и плейлистов для офлайна (Service Worker + Cache Storage, с перемоткой).
- **Текст песни как в караоке**: кнопка 🎤 в плеере. Синхронизированный текст из [LRCLIB](https://lrclib.net), запасной вариант — обычный текст из YouTube Music. Тап по строке перематывает на неё.
- **Настройка главной**: в «Настройках» можно скрыть любые разделы; настройка синхронизируется между устройствами.
- **Жесты**: удержание ⏮/⏭ перематывает на 5 с, удержание названия трека копирует «Артист — Название».
- **Адаптивный интерфейс**: телефон (вкладки + мини-плеер), планшет (боковая панель-иконки + панель плеера), ПК (полная боковая панель с плейлистами, громкость, плеер в две колонки с текстом). Горячие клавиши: Пробел, ←/→ (±5 с), Shift+←/→ (трек), M (звук).
- **Темы**: Графит, Чёрная (OLED), Полночь, Лес, Вино, Светлая, Сепия.
- **Языки**: русский, English, polski (или как в системе). Словари — `lib/locales/*.ts`, ключи — русские строки.
- **Статистика**: время прослушивания, топ артистов и треков, графики по дням, часам и дням недели, серия дней.
- **Умный буфер**: следующий трек скачивается заранее, последние 6 остаются на устройстве — переход вперёд/назад без загрузки.
- **Синхронизация между устройствами** мгновенная, через Supabase Realtime (включается в `schema.sql`).

## Как работают рекомендации

YouTube Music поставляет кандидатов: радио по треку (`getUpNext` automix), топ-треки артистов, похожих артистов.
Поверх этого `lib/recommend.ts` строит ваш вкус по артистам: выбранные артисты +4, лайк +2, дизлайк −3,
прослушивание до конца +0.4, пропуск в первые 30 с −0.8 (с затуханием за ~30 дней). Затем кандидаты
пересортировываются, дизлайкнутое и нелюбимые артисты выкидываются, недавно игранное понижается,
подряд не идёт больше одного трека одного артиста. Подбор для радио только фильтрует, порядок YouTube сохраняется.

## Архитектура

```
app/
  page.tsx               — Главная (миксы)
  search/ onboarding/ settings/ artist/[id] album/[id] library/ queue/
  api/search             GET ?q=&type=all|song|album|artist
  api/suggest            GET ?q=      — подсказки поиска
  api/artist             GET ?id=     — артист: треки, альбомы, синглы, похожие
  api/album              GET ?id=     — альбом с треками
  api/mix                GET ?a=artistIds&t=trackIds — кандидаты для главной
  api/artists/popular    GET          — артисты для онбординга
  api/related            GET ?id=     — радио
  api/prepare /api/stream             — прогрев и прокси аудио
  api/lyrics             GET ?id=&title=&artist=&duration= — текст (LRC)
  api/warm               GET          — «будит» функцию при запуске приложения
  api/debug              GET ?id=     — диагностика доступа к YouTube
public/sw.js             — офлайн-аудио (Range/206), кэш оболочки приложения
lib/recommend.ts         — вкус пользователя и ранжирование
lib/cloud-sync.ts        — синхронизация с Supabase по таблицам
lib/downloads.ts         — загрузки (3 параллельно, с прогрессом)
store/library.ts         — локальная медиатека (zustand + localStorage)
```

### Фоновое воспроизведение на iOS

1. **Один `<audio>`** живёт в `PlayerProvider` в корневом layout и никогда не пересоздаётся — меняется только `audio.src`.
2. **Синхронный `ended`**: URL потока предсказуем (`/api/stream?id=…`), поэтому следующий трек включается сразу, без `await`. Радио заранее дозаполняет очередь, когда до конца остаётся < 3 треков, так что следующий трек всегда известен.
3. **Прогрев**: за 20 с до конца трека уходит `fetch('/api/prepare?id=NEXT')` — сервер заранее получает ссылку на поток.
4. **Media Session**: метаданные с обложкой 544×544, `playbackState`, `setPositionState`, обработчики `play/pause/nexttrack/previoustrack/seekto`.

### Стриминг

- Выбирается лучший `audio/mp4` (AAC) — Safari не воспроизводит webm/opus стабильно.
- Range-запросы клиента транслируются в параметр googlevideo `&range=start-end` (не больше 10 МБ за ответ), сервер сам формирует `Content-Range`/`Content-Length`/`Accept-Ranges` → мгновенная перемотка.
- При 403/410 от CDN (ссылка истекла или привязана к IP другого инстанса) ссылка получается заново и запрос повторяется. Если `<audio>` выдаёт ошибку, клиент один раз повторяет с `&fresh=1`, затем пропускает трек.

### Хранилище

- Всегда: `localStorage` (zustand persist, `store/library.ts`) + синхронизация между вкладками — приложение работает и офлайн, и без аккаунта.
- После входа через Google: лайки, дизлайки, плейлисты, артисты, история прослушиваний и очередь лежат в таблицах Supabase (`lib/cloud-sync.ts`). Изменения отправляются через 1,5 с, при сворачивании приложения сразу; при возвращении подтягиваются изменения с других устройств.
- Скачанные треки хранятся только на устройстве (Cache Storage) и не синхронизируются.

## Ограничения

YouTube регулярно меняет защиту (PO-токены, проверка на бота для IP дата-центров). Если `/api/prepare` возвращает ошибку, сначала задайте `YT_COOKIE`, затем поменяйте порядок `YT_CLIENTS`. Используйте приложение в рамках условий YouTube.
